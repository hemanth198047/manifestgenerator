# Build and operations guide

The project is a single Gradle (Groovy DSL) application with **no libraries, no third-party Gradle plugins and no repositories**. Only Gradle's built-in `java` plugin is used, so nothing is
downloaded during a build once the JDK and Gradle themselves are provisioned.

## Prerequisites (provisional versions: replace with your approved ones)
| Item | Needed | Notes |
|------|--------|-------|
| JDK | 17 or newer, installed locally | `options.release = 17`. No toolchain auto-download is configured; Gradle uses the JDK it runs on. |
| Gradle | 8.x (provisional) from your approved distribution | Never executed against this build file by the author. |
| OS | Windows or Linux | No admin or root rights are needed to build or run. |

## Gradle Wrapper (generate it; do not type it)
The wrapper files (`gradlew`, `gradlew.bat`, `gradle/wrapper/*`) are generated by your approved Gradle and are not in the repository.
```
gradle wrapper --gradle-version <approved version> --gradle-distribution-url <internal URL ending in gradle-<version>-bin.zip> --gradle-distribution-sha256-sum <published SHA-256>
```
- Use your internal mirror's URL, or a pre-provisioned distribution (point `distributionUrl` at a `file:` URL). The wrapper must not download from a public URL unless policy allows it.
- Take the SHA-256 from a trusted source (your artifact repository or the publisher), not from the file you just downloaded.
- Offline mode works only after the exact Gradle distribution and JDK are provisioned: `./gradlew --offline jar unitTests`. There are no dependencies to cache.

## Commands
| Task | Linux (Bash) | Windows (PowerShell or cmd) |
|------|--------------|-----------------------------|
| Versions | `java -version; gradle --version` | `java -version` then `gradle --version` |
| Wrapper | `gradle wrapper ...` (above) | `gradle.bat wrapper ...` |
| Compile | `./gradlew compileJava` | `gradlew.bat compileJava` |
| Tests (built-in runner) | `./gradlew unitTests` | `gradlew.bat unitTests` |
| Package | `./gradlew jar` (produces `build/libs/casc-generator.jar`) | `gradlew.bat jar` |
| Dependency inspection | `./gradlew dependencies` (expect none) | `gradlew.bat dependencies` |
| Offline | `./gradlew --offline jar unitTests` | `gradlew.bat --offline jar unitTests` |
| Web UI | `java -jar build/libs/casc-generator.jar web` | `java -jar build\libs\casc-generator.jar web` |
| CLI | `java -jar build/libs/casc-generator.jar ingest --input-files "./my specs" --db-name DB --default-schema s --output ./manifest.json` | `java -jar build\libs\casc-generator.jar ingest --input-files ".\my specs" --db-name DB --default-schema s --output .\manifest.json` |
| Without Gradle | `bash infrastructure/ci/build-without-gradle.sh` | `powershell -File infrastructure\ci\build-without-gradle.ps1` |
| Verify a jar | `bash infrastructure/ci/verify.sh` | `powershell -File infrastructure\ci\verify.ps1` |

## If you later add an approved library
Nothing in the build needs a repository today. If you add one, configure only your internal repositories, with credentials supplied from the environment:
```groovy
// settings.gradle (plugins)                          // build.gradle (dependencies)
pluginManagement { repositories { maven {             repositories { maven {
    url = 'https://REPLACE-ME.internal/gradle-plugins'     url = 'https://REPLACE-ME.internal/maven-releases'
    credentials { username = providers.environmentVariable('REPO_USER').orNull
                  password = providers.environmentVariable('REPO_PASSWORD').orNull } } } }   // same credentials block here
```
Do not enable `mavenCentral()` or the Gradle Plugin Portal by default, and never commit credentials. Then use Gradle's built-in controls: dependency locking
(`dependencyLocking { lockAllConfigurations() }`, `gradle dependencies --write-locks`) and verification metadata (`gradle --write-verification-metadata sha256 help`).
Generated checksums are only a starting point: review them through your trusted process before accepting them. Each library also needs an entry in `docs/DEPENDENCIES.md` with its approval status.

## Operating the application
All settings use the same names on Windows and Linux.

| Setting | Bash | PowerShell |
|---------|------|------------|
| Port and bind address (default 127.0.0.1:8080) | `CASC_PORT=9090 CASC_BIND=127.0.0.1 java -jar build/libs/casc-generator.jar web` | `$env:CASC_PORT="9090"; java -jar build\libs\casc-generator.jar web` |
| Request body limit | `... web --max-body-bytes 10000000` | `... web --max-body-bytes 10000000` |
| Input boundary for `ingest` | `export CASC_INPUT_ROOT=/data/specs` | `$env:CASC_INPUT_ROOT="D:\data\specs"` |
| Allowed URL hosts, token | `export CASC_URL_ALLOW=wiki.corp.example; export CASC_URL_TOKEN=...` | `$env:CASC_URL_ALLOW="wiki.corp.example"; $env:CASC_URL_TOKEN="..."` |
| Truststore and proxy | `JAVA_OPTS="-Djavax.net.ssl.trustStore=/etc/casc/ts.p12 -Dhttps.proxyHost=proxy -Dhttps.proxyPort=8080"` | `$env:JAVA_OPTS="-Djavax.net.ssl.trustStore=C:\casc\ts.p12 -Dhttps.proxyHost=proxy -Dhttps.proxyPort=8080"` |
| Logs | The application logs to standard output and error only. `... web > casc.log 2>&1` | `... web *> casc.log` |
| Temporary files | Exports write a temp file next to the output and move it into place; nothing else is written to disk by the server. | same |

Console encoding: output is UTF-8. On Windows run `chcp 65001` first if non-ASCII text in the console looks garbled; files are always written as UTF-8.
There is no configuration file, no database, no browser auto-start and no service installation. An optional service deployment would need an approved service wrapper and is not provided.
Normal operation needs no administrator or root rights. Overwrite behaviour: `export` and `ingest` refuse to replace an existing output unless `--overwrite` is given; outputs are written atomically (with a plain move where atomic moves are unsupported).
